# Milestone 03 — AI gateway and curriculum generation

This B04 increment adds asynchronous generation to the B03 curriculum workflow. Its default is a deterministic synthetic demonstration, not a calibrated personalised learning model. Anthropic Messages and Gemini generateContent adapters are implemented and exercised using intercepted HTTP responses. No real credentials, paid calls or live provider validation were used.

## Try the local workflow

1. Run `php scripts/setup.php` to apply migrations without resetting the application database. Start the web server as described in the application README.
2. In separate terminals run `php artisan queue:work --queue=ai_generation --tries=1 --timeout=120` and `php artisan schedule:work`.
3. Sign in as Casey. Complete and confirm Sam's onboarding and shared calendar, then create a curriculum draft (Milestone 02). A four-block, Monday-only plan with 30 minutes per day is a compact demonstration.
4. In the curriculum editor expand **Generate or revise with AI**, optionally enter revision notes and click **Queue curriculum generation**. Progress polls an authorised endpoint. The request survives leaving the page; find it under recent generation requests in the editor.
5. Open **Review generated draft** when all blocks finish. Inspect all lessons, the previous-version comparison, rubric, source and time allocations. The mock always supplies the same synthetic procedure-writing demonstration; it records but does not interpret revision notes or personalise lessons.
6. Use **Validate all blocks and request review**, then record coordinator approval. Generation alone never approves content, changes targets or activates training. An existing approved baseline stays approved until a replacement is explicitly approved.
7. Sign in as Alex and open **AI settings** to view the qualified registry, save a versioned route, or reconcile uncertain charges. This screen does not expose raw learner inputs or secret values.

## Contracts and policy

- Registry entries live in `config/ai.php`: adapter, exact model, configuration/rate versions, allowed purpose/data class, fixed endpoint, secret reference, input/output limits and rate limit. Add separately named entries to offer additional exact models. Secrets are resolved only inside the server transport. Administrator route revisions are immutable database records with optimistic version checks; model and price qualification remains deployment-controlled.
- Each run pins the policy, complete provider configuration, prompt hash/version, block schema version, base programme, onboarding/calendar references and revision notes. Queued calls also recheck current provider enablement and allowed data classification; revocation prevents new calls.
- Routing stores all four planned task names. Curriculum generation is the implemented workflow. Grade/adaptation/KPI task execution and their domain-specific output validators belong to B05/B06; their route settings alone do not implement those workflows.
- The live adapters follow [Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create) and [Gemini generateContent](https://ai.google.dev/api/generate-content). Each uses its provider's own payload, credential header, text and usage mapping. Neither enables tools, file upload, code execution or browsing. Fixed HTTPS endpoints and disabled redirects prevent arbitrary destination fetches. Resource references are never fetched by this gateway.
- Generation sends the profile, confirmed findings/evidence kind, targets, KPIs, approved resource, block dates, draft block and revision notes. Identity records, person names from identity tables and uploaded files are excluded. Free-text fields can still contain personal data; qualification must consider the entire confirmed-training data class.
- Every generated lesson must reference the exact resource ID derived from the immutable onboarding revision. The validator rejects extra fields, invented source/KPI/competency references, missing usable-content fields, changed dates, invalid prerequisite order, negative or excessive minutes and rubric weights that do not total one. Full programme validation and shared capacity are checked again before saving a new draft. Automated checks cannot establish pedagogical quality or source truth; human review remains required.
- The JSON contract is application-validated. Gemini requests JSON mode; Anthropic receives the versioned JSON instruction and shape. Invalid output gets at most one repair attempt. Refusals and truncations fail visibly. No unchecked prose is substituted.

## Queue, cost and recovery

- Requests serialize on the organisation budget lock, then the existing member/enrolment locks. Idempotency keys are actor-scoped and bound to enrolment, base version and feedback. Different input under the same key returns 409. One pending/uncertain run per enrolment prevents accidental overlapping generation.
- Each block has a durable dispatch row and each provider call has a unique attempt row. Queue payloads contain only the block ID. Dispatch occurs after commit; `training:ai-recover` recovers missing dispatches. Two workers receiving the same block cannot both claim a provider call.
- Initial concurrency is one in-flight call per organisation. Provider request rate limits defer excess work. Deferred blocks remain queued for scheduler recovery. Use a dedicated AI worker so generation cannot starve notification work.
- HTTP timeout is 90 seconds, job timeout 120, queue retry-after 180. An expired running attempt becomes `ambiguous`; it is never blindly reissued. The job itself has one try; application-controlled retries are separately recorded attempts.
- HTTP 429 may retry up to three times with delay/jitter; it may switch only to the run's explicitly permitted fallback and records an audit event. Timeouts, interrupted workers, server errors and missing usage retain reservations because upstream completion/billing is unknown. Credentials, refusal and other rejected requests fail without repeated calls. A new generation is always an explicit user request.
- Budgets are lifetime organisation/environment and per-enrolment caps, in integer micro-USD (one million equals USD 1). Admission reserves a conservative full input-byte/output-token allowance for up to five calls per block, including repair/retries, at the most expensive permitted route. Known usage moves from reserved to spent; terminal known outcomes release unused funds. Ambiguous completion retains the remaining hold. Mock prices are simulated ledger values only.
- Administrators reconcile an ambiguous run against billing evidence, supplying a reason and total including all known calls. This records an audit event, releases the hold and closes the run as failed. It does not automatically regenerate. Provider billing idempotency is not assumed.
- `training:ai-prune` clears temporary block outputs and revision notes from terminal runs older than 30 days. Saved curriculum versions, references, accounting and audit history remain. Full retention/legal holds, provider-side erasure and pending-job expiry are later operations work.
- On a deployment restart workers with `php artisan queue:restart`. Run recovery before resuming work. Do not roll back this migration while AI runs are queued or charges unresolved; pause the AI worker, account for requests, back up, then use a coordinated application/schema rollback.

## Verification and remaining gates

Tests cover mock draft completion, exact input versions, stale/revoked access, request deduplication, budget denial, schema/semantic failures, one repair, refusals, bounded throttling/fallback, interrupted calls, charge reconciliation, old-trace pruning and approved-baseline preservation. Adapter tests intercept both REST protocols and reject redirected/private destinations. MariaDB includes a real two-process duplicate-worker test. Browser tests exercise generation through a real database queue, live progress, draft review, routing and mobile accessibility.

Local verification on 1 October 2026: all 65 SQLite tests passed, and the 19 generation tests passed again after the final registry allowlist change. The MariaDB suite passed 68 tests before the additional budget-concurrency scenario; both final AI concurrency tests then passed. All six browser tests passed; the coordinator journey passed again after the progress/attempt-list fix. Pint, Composer validation, Blade compilation and non-destructive application setup passed. The local login responded HTTP 200. Evidence: [mobile generation progress](evidence/generation-complete-mobile.png), [generated draft](evidence/generated-draft.png). Hosted CI on the PR supplies the final clean-checkout counts.

The CI workflow runs these tests in clean checkouts. Live provider access, exact production model/prices/data handling, output quality calibration, document extraction/scanning, learner activation/submissions/grading, adaptation and KPI execution remain unimplemented or unverified as noted. T15 generation validation and T16 local resilience are covered; live failure behavior and grading evidence validation are later gates.
