## Runtime

The locked local build uses Laravel 12.69.3, Livewire 3.8.10 and PHP 8.2-compatible dependencies. The workstation PHP 8.2.12 is a local development runtime; choose a current patched supported PHP runtime before deployment. Laravel 12 was selected to match this machine and its security support ends 24 February 2027: https://laravel.com/framework/docs/12.x/releases. Plan the PHP/Laravel upgrade before that boundary.

MariaDB 11.4.13 was verified in an isolated workspace instance. Series support reference: https://mariadb.org/mariadb-server-12-3-11-8-11-4-and-10-11-q3-2026-maintenance-releases-and-goodbye-10-6/. SQLite is the zero-service local default; it does not establish production concurrency or performance.

For an existing authorised MariaDB development database, set DB_CONNECTION=mariadb, DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME and DB_PASSWORD in the ignored .env. Use a dedicated database/user. Never point test configurations at a valuable database: RefreshDatabase recreates tables. phpunit.mariadb.xml forces training_foundation_test and defaults to local port 3308. Override host/port/user/password through the process environment for your own isolated test server.

## Local processes

From platform:

- Web: php artisan serve --host=127.0.0.1
- Worker: php artisan queue:work --queue=notifications --tries=3 --timeout=120
- Scheduler: php artisan schedule:work
- One-shot dispatch recovery: php artisan training:outbox
- Drain queued checks: php artisan queue:work --queue=notifications --stop-when-empty --tries=3

The application uses database sessions, cache locks and queues. Queue retry_after is 180 seconds, above the 120-second job timeout. Failed jobs exhaust a bounded retry budget and are marked failed, rather than automatically requeued forever. Operators should diagnose the failure before a deliberate replay. Keep one scheduler; duplicate outbox jobs are harmless because delivery locks the event and the database sink has a unique event constraint.

A business event and audit entry commit atomically. Queue dispatch occurs after commit. The recovery command discovers a committed event even when the initial dispatch was lost. Delivery rechecks current actor/organisation/group/enrolment authority and the enrolment version, and cancels revoked/stale work. Sink insert and delivered state commit in one transaction. SMTP is not implemented; no claim of exactly-once external delivery is made.

## Evidence storage

Files live under storage/app/private, never public/storage. Automatic local temporary serving is disabled. A controller rechecks scope and the sensitive-assessment capability and writes a download audit event. New uploads accept PDF/PNG/JPEG up to 20 MiB and always remain quarantined; they cannot be downloaded. Trusted synthetic text fixtures are generated by the seeder.

Real malware scanning, DOCX/macro validation, constrained extraction and OCR are pending. Do not mark arbitrary uploads clean or accept real employee data. The current upload route treats all new uploads as sensitive.

## Release and rollback boundary

This milestone is not deployable as a live training service: production identity is deliberately unavailable. No remote push or deployment was performed.

Before an authorised release: confirm host/PHP/database versions, backups, secrets, private public-root separation, worker supervision, HTTPS secure cookies, trusted proxy configuration, real integration policies and approval workflows. Take database/file/key backups before migrations; review the migration plan, migrate once, restart workers, smoke-test access, then release traffic. A code rollback does not undo data migrations; use a tested compatible migration/restore procedure. Never run migrate:fresh on operational data.

The foundation migration includes down methods and reverse dependency ordering. Full recovery, encrypted off-host backups, deletion ledger, retention holds/erasure, monitoring and load benchmarks belong to B08 and have not been proven by this milestone.

## User guide

Choose a synthetic identity on the local sign-in page. Members see one assigned plan; coordinators see their assigned group's plan; the administrator sees both plans and the People list. Open a plan to download the supplied private fixture or queue a foundation check. Run the worker to see a Delivered receipt. Uploads demonstrate quarantine only, not assessment submission or grading.

No lessons, curriculum approval, grading or KPI results are implemented in this milestone.
