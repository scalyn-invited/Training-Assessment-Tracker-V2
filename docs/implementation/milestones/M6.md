## Bernie responsibilities

- Implement bounded server-side approved context retrieval and allowlisted tool restrictions using shared access services.
- Implement private conversation lifecycle/retention, gateway integration, cost reservation and permission/content-version cache partitioning.
- Test injected prompts/documents, forged sources, peer/cross-client leakage and revocation races.
- Exclude raw sensitive assessments, provisional results, answer keys and private notes by default; chat cannot mutate grades, plans, permissions or budgets.
- Start with relational retrieval. Do not add paid vector hosting/embeddings, unrestricted SQL, URL fetching or autonomous actions without a separate approved scope.

## Saturnino responsibilities

- Design the simple training chat UI, scoped history, grounded citations and clear advisory status; implement only bounded presentation slices against stable C06 fixtures.
- Review accessibility and user-facing forged/expired citation and provider/limit error states; Bernie owns access, security and revocation checks.
- Exercise the six example questions in PDF section 19 and provide a contact-coordinator route when context is absent.
- Keep approved source visibility intact; do not render or cache another member’s answer/history in the browser.
- Prefer complete authorised responses for MVP; any streaming change must address mid-response revocation and be reviewed with Bernie.

## Milestone acceptance

- PDF section 19 example questions receive useful answers grounded in the current member’s authorised approved context.
- Cross-client/team/peer requests, injection, forged citations and guessed conversation IDs reveal no data.
- Revocation between retrieval and response or citation opening denies access; caches/history remain scoped.
- The chatbot is advisory/read-only with bounded context, rate/spend controls and recoverable provider failure.
