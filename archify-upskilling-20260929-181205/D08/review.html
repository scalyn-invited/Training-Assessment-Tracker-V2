Nodes and ownership
  • Onboarding — Profile and calendar (onboarding)
  • Ready — Baseline approved (ready)
  • Active — Approved lessons (active)
  • Completed — Human final approval (completed)
  • Paused — Preserve attempts (paused)
  • Cancelled — Terminal · history kept (cancelled)
Directed relationships
  1. onboarding → ready: Approve baseline
  2. ready → active: Activation checks
  3. active → completed: Evidence sufficient
  4. active → paused: Approved leave
  5. paused → active: Resume + rebase
  6. active → cancelled: Cancel
Readiness and completion
  • Reject activation until baseline content for every week is approved; current + next remain usable. Completion requires sufficient approved evidence, required tasks and coordinator confirmation.
  • 4/6/8/10/12 blocks. Time spent never automatically proves competence or completes an enrolment.
Calendar changes
  • Pause preserves active work and attempts. Resume previews shifted future dates and creates a calendar version; recompute holiday-aware cutoffs.
  • All programmes share one capacity calendar, 15–120 minutes per active day including assessment/revision. Do not rewrite completed history.
Separate programme version state
  • Programme version: draft → generating → needs_review → approved → superseded; generation_failed returns to correction. These are not enrolment states.
  • Enrolment has one accountable coordinator. Permission and optimistic version checks apply to activation, pause, resume and completion.
